Solwyn Engineering · Design Specification

Provider Failover — Design Spec

True health-based cross-provider failover: a transparent drop-in surface, an internal canonical request, and a classified candidate-walk that fails over only when it can prove the request never durably landed.

Section 01

Executive Summary & Recommendation

Verdict. Build true health-based cross-provider failover by replacing today's single-provider dispatch with a four-seam architecture: an ordered ProviderRuntime registry, a pure SelectionPolicy/Router (health-only now, latency/cost-ready), a single content-privileged RequestTranslator that owns a deliberately tiny common subset and fails loudly on anything outside it, and a classified candidate-walk dispatch loop that fails over only when it can prove the original request never durably reached the primary. Roughly two-thirds of the plumbing (per-provider circuit breakers, extraction adapters, _AttemptContext, per-served-provider metadata/budget) already exists; this is additive seam-work, not a rewrite.

Transparent-vs-normalized verdict (grounded in industry research). Keep the transparent drop-in Solwyn(primary_client) request surface — users keep calling their native client (client.chat.completions.create(...)). The industry's client-side libraries (LiteLLM Router, LangChain with_fallbacks) all normalize internally while exposing a familiar surface; "OpenAI-compatible" is the de-facto normalization standard. We adopt that pattern's spirit: native request surface, an internal canonical request, owned translation only on the cross-provider hop. On the response side we normalize back to the caller's native shape — returning a foreign provider object from a call made in OpenAI dialect is a silent AttributeError waiting to happen and directly violates the "your agents don't go down" promise. Response normalization lives behind one seam; streaming failover is first-byte-only and v1 may ship non-streaming failover first.

Decision · Surface

Native request surface in, caller-native response shape out. Translation activates only on a real cross-provider hop; the 99% native path pays zero translation overhead and gains zero new surface area.

What we will build

  • Config (breaking): replace fallback_model: str | None with an ordered providers: list[ProviderEntry] chain (each entry = provider + per-provider model + optional creds/client). Same-provider model swap becomes a repeated-provider entry.
  • _registry.py — ProviderRuntime = (entry, sdk_client, adapter); holds all chain clients, built at __init__.
  • _routing.py — SelectionPolicy Protocol + HealthBasedPolicy; returns an ordered candidate list (the seam for latency/cost later). Ordering uses non-mutating breaker state reads.
  • providers/_translation.py — the only new content-touching module; canonical request/response + per-provider translators; fails loudly via UntranslatableRequestError. PRIVACY-CRITICAL banner, no logging/httpx.
  • providers/_errors.py — classify_exception() per adapter, status-first, APITimeoutError matched before APIConnectionError.
  • Dispatch rewrite — candidate walk with a mandatory chain deadline + per-hop timeout/max_retries=0, idempotency-gated failover, first-byte streaming rule.
  • Cloud API contract sync — provider (required) added to BudgetConfirmRequest; advisory chain hint on BudgetCheckRequest; failover observability fields on MetadataEvent; server-side reservation TTL.
  • Firewall hardening — allowlist-based privacy tests + end-to-end sentinel-in-payload test.
Decisions ratified · 2026-06 maintainer review (supersedes the matching items in §11)

A · Streaming is in v1. Streaming failover ships with the first release (high-value, not deferred): first-byte-only rule across wrappers + Google first-chunk materialization so its lazy generator is failover-eligible. The response is normalized back to the caller's native shape, streaming included.

B · Tools are in the failover subset — with a hard stateless/stateful line. Translate the converged custom-function contract (JSON-Schema declaration + tool_choice, and fully-resolved tool histories). Fail loud on dangling/unresolved tool calls at the failover boundary, parallel same-name calls, and all proprietary tools. Bidirectional round-trip tests are the drift alarm (event-driven, not perpetual); a tool_call_not_failoverable metric drives data-driven scope growth.

C · Safe-by-default, aggressive-by-opt-in. failover_idempotency="safe" (no double-charge) is the default and the floor. Aggression is explicit: failover_idempotency="always", the per-call solwyn_idempotent override, and a tunable failover_total_timeout.

D · Provider credentials are out of scope (core tenet). Solwyn never accepts, stores, or logs provider API keys (or prompts). Provider creds come solely from the SDK client objects the caller constructs; the SDK only requires — and documents — that they be set. ProviderEntry carries no api_key/base_url.

E · Per-provider default params. Callers who know both providers may preset fill-absent defaults (e.g. max_tokens) globally and per provider entry. Precedence: per-call kwargs > per-entry default_params > global default_params; defaults fill absent fields only, never override a provided value.

F · Provider-SDK version floors. Declare minimum versions for the provider libraries in the install extras (solwyn[openai]/[anthropic]/[google]) so exception classes, max_completion_tokens, and the google-genai surface are predictable. The core still depends only on httpx+pydantic; status-first classification (§6.1) stays the runtime net for bring-your-own-client installs that bypass the extra.

Section 02

Problem & Current-State Gap

Solwyn already reports per-provider circuit state and keeps one breaker per provider in a dict (_base.py), yet it can never route to a second provider. Three structural couplings pin every call to exactly one provider:

#CouplingLocationEffect
1 One client/adapter/provider fixed at construction client.py __init__: self._client, self._adapter, self._detected_provider No place to hold a second SDK client or its creds
2 _select_provider() is structurally single-provider _base.py:139-162 — returns self._config.primary_provider.value or raises ProviderUnavailableError The per-provider breaker dict is decorative for routing; selection can never name a second provider
3 Dispatch is a hardcoded if provider == … ladder client.py _sync_dispatch/_async_dispatch Calls exactly one native method shape; never changes client/adapter/request shape

The only real fallback today is a same-provider model swap. On a primary failure, _intercepted_call retries once with kwargs['model'] swapped to config.fallback_model on the same client (_should_retry_with_fallback / _prepare_fallback_kwargs in _base.py). The request shape never crosses providers — each proxy passes native kwargs straight through, and the three call shapes differ structurally (OpenAI messages; Anthropic messages + top-level system + required max_tokens; Google contents + config). True failover therefore requires the one genuinely new capability: request/response translation.

Reusable as-is

circuit_breaker.py (already per-provider), extraction adapters + stream accumulators (already normalize usage), _AttemptContext, reporter.py, per-served-provider provider= in budget/metadata.

Missing: multi-entry registry, a router that can pick a non-primary entry, a translator, and a re-selecting dispatch loop.

3.2  "OpenAI-shaped surface, normalized core" is the winning pattern

Two non-competing winning positions exist. Gateways expose an OpenAI-compatible REST surface and translate server-side. Client libraries expose either OpenAI-compat signatures (LiteLLM) or a normalized interface (LangChain/Vercel) and translate inside the library. Both own the translation layer. The "transparent vs normalized" framing is a false dichotomy: OpenAI-compat is the normalization standard. Multi-provider failover is not niche — OpenRouter raised a $113M Series B (May 2026) on routing alone; Portkey was acquired by Palo Alto Networks (Apr 2026). The dominant trigger is rate limits (429) as much as outages.

3.3  What being a CLIENT-side SDK constrains

  • No mid-stream recovery. Bytes already forwarded to the user cannot be un-sent. Every production system (Sierra, Assembled, LLM Gateway) fails over only before the first token — this is the universal norm, not a Solwyn-specific weakness.
  • Credential sprawl. The app must provision keys for every provider in the chain (a gateway holds them centrally). This is an adoption-friction reality to document.
  • Process-local health. A fresh process starts with all breakers CLOSED; the first failing request of any new process always pays full freight. Shared by LiteLLM Router and LangChain.
  • What we gain: no extra infra, no proxy hop, lower p50 — exactly the "client-side, no server in the loop" differentiator the marketing promise rests on. (Note: Solwyn's Cloud API for budget/metadata already exists; "no server in the loop" refers to the routing decision being local, not zero network calls.)
Section 04

Recommended Architecture

Per-provider circuit-breaker state flow
Closed → Open → Half-Open → Closed
Closed → Openfailure_threshold consecutive failures recorded; route stops attempting this provider.
Open → Half-OpenAfter recovery_timeout (±20% jitter) a single probe slot opens; consumed only by the candidate actually attempted.
Half-Open → ClosedProbe success: breaker resets, provider returns to healthy rotation.
Half-Open → OpenProbe failure: breaker re-opens; the loop advances to the next candidate.

4.1  Chosen surface

  • Request: transparent drop-in. Solwyn(OpenAI()) stays; the user calls their primary client's native methods.
  • Response on failover: normalize back to the caller's primary shape via a single _translate_response_out seam (non-streaming v1). Do not hand back a foreign provider object — that silently breaks resp.choices[0].message.content.
  • Translation activates ONLY on a real cross-provider hop. The native happy path and same-provider model swap pass kwargs straight through — zero translation overhead and zero new surface for the 99% case.

4.2  The Router / SelectionPolicy seam

The router is a pure, sans-I/O function over (ordered runtimes, breaker dict) returning an ordered candidate list. Returning a list (not a single provider) is what makes latency/cost routing a drop-in later: a future policy only reorders — it never touches I/O, breakers, or budget.

src/solwyn/_routing.py · sans-I/O
# src/solwyn/_routing.py  (sans-I/O)
class ProviderCandidate(BaseModel):
    runtime: ProviderRuntime
    breaker_state: CircuitState        # non-mutating read
    translatable: bool                 # per-target predicate (future cost/latency policies need this)
    price_hint: float | None = None    # populated later from a SERVER-provided relative-price signal

class RoutingRequest(BaseModel):
    requested_provider: ProviderName
    estimated_input_tokens: int        # already computed; enables cost routing later
    # additive-only; extra="forbid" preserved

class SelectionPolicy(Protocol):
    def order(self, candidates: list[ProviderCandidate], req: RoutingRequest) -> list[ProviderCandidate]:
        """Pure, side-effect-free. Return runtimes in attempt order; [] => all unavailable."""

class HealthBasedPolicy:
    """v1 default: config order, CLOSED before HALF_OPEN-eligible. Never promotes an untranslatable target."""
    def order(self, candidates, req):
        prio = {CircuitState.CLOSED: 0, CircuitState.HALF_OPEN: 1, CircuitState.OPEN: 2}
        usable = [c for c in candidates if c.breaker_state is not CircuitState.OPEN or c.recovery_eligible]
        return sorted(usable, key=lambda c: (prio[c.breaker_state], not c.translatable))
Critical correctness rule — separate INSPECTION from CONSUMPTION

circuit_breaker.can_proceed() mutates state (an OPEN-but-recovery-eligible breaker flips to HALF_OPEN and returns True). The router must order using non-mutating breaker.state reads, and call can_proceed() only on the single candidate actually being attempted. Calling can_proceed() across all candidates up front would flip every recovery-eligible breaker to HALF_OPEN at once, silently consuming all probe slots.

How latency/cost routing slots in later (no refactor)

  • Latency: new LatencyPolicy(SelectionPolicy) sorts the same candidates by observed p50. Pure drop-in.
  • Cost: NOT a pure drop-in by itself — the SDK must never compute price. It requires (a) a new server-provided relative-price hint on BudgetCheckResponse (or a side endpoint) to populate ProviderCandidate.price_hint, and (b) the translatable predicate already on the candidate. We design both fields now so cost routing is additive later, but flag the new server field as a prerequisite.

Decisions D & E — credentials out, default_params in

No provider keys, ever. ProviderEntry deliberately omits api_key/base_url: Solwyn never accepts, stores, or logs a provider credential. Creds live in the client objects the caller constructs (OpenAI(), Anthropic(), …), which read their own environment. The SDK only requires that each chain provider's creds be present, and documents this.

default_params precedence: per-call kwargs > per-entry default_params > global default_params. Defaults fill an absent field only — they never override a value the caller passed. Safe for a required field like max_tokens (resolves the old §11 Q3); a semantic-range field like temperature>1.0 still fails loud rather than clamps.

Env loading regression — deliberate, accepted (zero customers)

Flat env vars cannot express an ordered chain. SOLWYN_FALLBACK_MODEL is removed; env supports the single-primary case only. Multi-provider chains are code-constructed.

All chain clients are constructed at __init__ so the first failover is pure dispatch (no client-construction latency inside the user's request). Provider credentials live entirely in those client objects — Solwyn never sees, accepts, or stores a provider API key (Decision D).

4.6  Revised dispatch flow (sync; async mirrors with await)

Carries the full attempted chain. Post-send-ambiguous failures re-raise the original provider exception instead (drop-in contract).
def _intercepted_call(self, *, _force_stream=False, **kwargs):
    requested_model = kwargs["model"]
    is_streaming = bool(kwargs.get("stream")) or _force_stream
    primary = self._runtimes[0]
    deadline = Deadline(self._config.failover_total_timeout)   # covers budget pre-flight too

    # 1+2. Estimate + budget — against the PRIMARY (we don't yet know who serves).
    char_count = estimate_content_length(kwargs)               # _privacy.py ONLY
    est_in = estimate_tokens_from_length(char_count, primary.adapter.name) if char_count else 0
    budget = self._budget.check_budget(estimated_input_tokens=est_in,
                                       model=requested_model, provider=primary.adapter.name,
                                       fallback_providers=[r.entry.provider for r in self._runtimes[1:]],
                                       fallback_models=[r.entry.model for r in self._runtimes[1:]])
    if not budget.allowed:
        self._reporter.report(self._build_error_event(..., reason=BUDGET_DENIED))
        raise BudgetExceededError(...)

    # 3. Router returns ordered, health-filtered candidates (non-mutating state reads).
    candidates = self._select_candidates(RoutingRequest(requested_provider=primary.entry.provider,
                                                         estimated_input_tokens=est_in))
    if not candidates:
        raise ProviderUnavailableError("all providers unavailable", attempted=[...])

    last_exc = None
    for idx, rt in enumerate(candidates):
        if deadline.expired():
            break
        provider = rt.adapter.name
        cb = self._get_circuit_breaker(provider)
        if not cb.can_proceed():            # probe CONSUMED only here, for the attempted provider
            continue
        is_provider_fallback = rt.entry.provider != primary.entry.provider

        # 4. Translate ONLY when crossing providers (may RAISE before any network call).
        try:
            if is_provider_fallback:
                canonical = self._adapter.to_canonical(kwargs)               # source = primary
                call_kwargs = rt.adapter.from_canonical(canonical, model=rt.entry.model)
            else:
                call_kwargs = {**kwargs, "model": rt.entry.model}            # same-provider model swap
        except UntranslatableRequestError:
            raise                            # class C — abort the WHOLE chain, do not try more providers
        if is_streaming:
            call_kwargs = rt.adapter.prepare_streaming(call_kwargs)

        ctx = _AttemptContext(model=rt.entry.model, start_time=time.monotonic(),
                              is_provider_fallback=is_provider_fallback, attempt_index=idx)
        try:
            # MANDATORY per-hop bound: kill the 600s default read window; no SDK-internal retry stacking.
            response = self._sync_dispatch(rt, call_kwargs, _force_stream=_force_stream,
                                           timeout=deadline.remaining(), max_retries=0)
        except Exception as exc:
            disp = rt.adapter.classify_exception(exc)        # status-first; APITimeoutError before APIConnectionError
            cb.record_failure()                               # one failure on THIS provider's breaker
            self._reporter.report(self._build_error_event(
                model=rt.entry.model, provider=provider,
                latency_ms=ctx.elapsed_ms(), is_provider_fallback=is_provider_fallback,
                failover_error_class=type(exc).__name__, attempt_index=idx))
            if disp is Disposition.FAIL_FAST:
                raise                                         # 4xx/404/refusal — do NOT advance the chain
            if disp is Disposition.POST_SEND_AMBIGUOUS and self._config.failover_idempotency != "always":
                # cannot prove the request didn't run -> never double-charge across providers
                raise                                         # re-raise ORIGINAL exception (drop-in contract)
            last_exc = exc
            continue                                          # pre-send safe -> advance to next provider

        # 6. SUCCESS — settle against the SERVED runtime.
        cb.record_success()
        if is_streaming:
            return self._wrap_stream(rt, response, ctx, budget, primary)   # normalization in wrapper
        token_details = rt.adapter.extract_usage(response)
        if budget.reservation_id:                              # cache-hit calls have reservation_id=None
            self._budget.confirm_cost(budget.reservation_id, rt.entry.model,
                                      token_details, provider=provider)     # provider NOW required
        self._reporter.report(self._build_metadata_event(
            model=rt.entry.model, provider=provider, is_provider_fallback=is_provider_fallback,
            requested_provider=primary.entry.provider if is_provider_fallback else None,
            requested_model=requested_model if is_provider_fallback else None,
            failover_reason=FailoverReason.CIRCUIT_OPEN if is_provider_fallback else None,
            attempt_index=idx, service_tier=rt.adapter.extract_service_tier(response)))
        # response normalized back to the caller's native shape on the failover path:
        return self._translate_response_out(served=provider, requested=primary.entry.provider, response=response)

    raise last_exc or ProviderUnavailableError(...)
Same-provider double-count guard — do NOT delete the old invariant

When two consecutive chain entries share a provider (the folded model-swap case), record_failure() must record at most one failure on that provider's breaker per logical attempt — otherwise the breaker opens twice as fast as configured. Port this explicitly; cover with a regression test mirroring test_circuit_breaker.py / test_fallback_model.py.

Section 05

Cross-Provider Translation Contract

Stance — minimize the SDK-owned surface. The translator owns a tiny canonical request/response. Anything outside it raises (UntranslatableRequestError) on the first cross-provider hop, before any network call. The native single-provider path is never validated or translated — full provider features keep working; only cross-provider failover is constrained. This is a deliberate product tension: the most feature-rich (tool-using, structured-output) calls are the least failover-capable. That is acceptable per the maintainer's fail-loud decision.

Decision B — tools ARE in the subset, with a hard stateless/stateful line

Why this is not a perpetual-patch treadmill. The custom-function contract (JSON-Schema body + tool_choice) has converged across all three providers and is low-churn; only proprietary tool types keep moving, and those are already fail-loud. Translate the stable core; never chase the moving parts.

Supported: tool declarations + tool_choice, and histories whose tool exchanges are fully resolved (mechanical block reshape + consistent id remap — the stateless case). Fail loud: a dangling/unresolved tool call at the failover boundary, parallel same-name calls, and all proprietary tools (the stateful/exotic cases).

Maintenance model: bidirectional round-trip tests are the contract and the drift alarm — work is event-driven (a test breaks ⇒ a provider changed the stable core, rare), not continuous. Emit a tool_call_not_failoverable metric so any subset expansion is driven by real customer impact, not speculation. A more conservative v1 line is also valid: declarations yes, any tool history fails loud.

5.4  Multimodal, finish reason, usage

  • Images: base64 inline translates cleanly across all three. Corrected: current Anthropic and Gemini both accept direct public HTTPS image URLs, so a plain public URL also translates. Section 06

Reliability Design

6.1  Error taxonomy (classify STATUS-FIRST, never class-name-first)

Class names diverge across SDKs and across versions. Solwyn's core still depends only on httpx + pydantic; Decision F adds minimum-version floors for the provider libraries via the install extras (solwyn[openai]/[anthropic]/[google]) so exception classes and params are predictable on the happy path. But clients remain bring-your-own — a user can install below the floor or bypass the extra — so the SDK cannot hard-assume any specific exception class exists at runtime (OverloadedError/ServiceUnavailableError/DeadlineExceededError appear and disappear across versions). This keeps status-first, duck-typed classification mandatory as the safety net. Use getattr(exc,'status_code',None) (OpenAI/Anthropic), getattr(exc,'code',None) (Google APIError), and isinstance on httpx transport errors for Google pre-send failures. Default unknown → FAIL_FAST (never failover into the unknown).

POST_SEND_AMBIGUOUS

Request may have run. Re-raise the original exception; never failover.

FAIL_FAST

The double-spend trap — verified, critical

APITimeoutError subclasses APIConnectionError in both openai and anthropic. A naive except APIConnectionError: failover catches the unsafe post-send timeout. The classifier must check APITimeoutError (and httpx.ReadTimeout for Google) first → POST_SEND_AMBIGUOUS, before the bare APIConnectionError/httpx.ConnectError pre-send branch. Prefer matching httpx.ConnectError/ConnectTimeout specifically for the "safe" path.

Google specifics

Errors are only APIError/ClientError/ServerError, keyed on .code (int). 429→pre-send SAFE; 4xx→FAIL_FAST; 5xx (ServerError)→POST_SEND_AMBIGUOUS (Google has no idempotency key — a re-send is an unconditional double-charge); raw httpx.ConnectError/ConnectTimeout→SAFE; httpx.ReadTimeout→UNSAFE. Put shared transport classification in providers/_errors.py; only provider-specific status/code mapping lives per-adapter.

6.2  Routing / retry ordering

  • No Solwyn same-provider retry by default (same_provider_retries=0). Each provider SDK already did up to max_retries=2 with backoff before raising; stacking more inflates tail latency. The one exception: a 429 with a short Retry-After on a non-idempotent call where failover is unsafe → a single bounded wait+retry on the same provider, respecting the deadline.
  • Never re-invoke .create() for "idempotent" same-provider retry — the SDK auto-generates a new idempotency key per top-level call, so a fresh .create() is not deduped. SDK idempotency only protects retries inside one .create() invocation.
  • On failover, pass client.with_options(timeout=remaining, max_retries=0) so the chain does not multiply SDK-internal retries across N providers.

6.3  Chain deadline budget (MANDATORY)

The default OpenAI/Anthropic read timeout is 600s. A hung-but-connected provider × 2 internal retries × 3-failure threshold can stack to ~30 minutes before the breaker even opens. A Deadline is therefore not optional:

  • Compute once at _intercepted_call entry from failover_total_timeout (default 30s). It encompasses the budget pre-flight (the budget httpx client's own 5s timeout counts against it).
  • Check before every hop; pass a shrinking per-hop timeout = max(floor, remaining/len(remaining_candidates)) plus max_retries=0.

6.4  Half-open & jitter

  • Order candidates by non-mutating state; consume the probe via can_proceed() only on the attempted candidate (§4.2).
  • A HALF_OPEN probe failure re-opens that provider's breaker (correct) and the loop advances — no special "skip record_failure" hack needed across different providers. The only invariant to preserve is the same-provider double-count guard (§4.6).
  • Add ±20% jitter to recovery_timeout (circuit_breaker_recovery_timeout_jitter) so a fleet of N processes doesn't probe the recovering primary in lockstep (anti-stampede).

6.5  Idempotency & double-spend safety rule

Cross-provider failover is permitted ONLY when Solwyn can prove the request was never durably accepted by the first provider — i.e. a pre-send failure (connect-refused/DNS/TLS, or an explicit pre-processing rejection: 429/529). On any post-send-ambiguous failure (read timeout, mid-stream reset, 5xx-after-send, 503), Solwyn MUST NOT failover; it re-raises the original provider exception unchanged and lets the caller decide.

  • Cross-provider idempotency keys do not exist — a key in OpenAI's dedup store is meaningless to Anthropic. No header can prevent a double-charge after a post-send failure.
  • failover_idempotency: safe (default, the rule above) · never (breaker still tracks health, no cross-provider failover) · always (caller asserts every request idempotent; loud warning at construction). Per-call override: solwyn_idempotent=True/False (stripped before dispatch).
  • Preserve the drop-in contract: on a post-send no-failover decision, re-raise the original exception type (e.g. APITimeoutError) so the user's existing except handlers fire — do not synthesize a Solwyn error. Solwyn-specific errors are reserved for chain exhaustion (ProviderUnavailableError, carrying the full attempted chain).
Decision C ratified — safe default, aggressive by explicit opt-in

safe is the shipped default and the non-negotiable floor: never double-charge. Clients who accept the risk opt in themselves — failover_idempotency="always" (assert all requests idempotent), the per-call solwyn_idempotent=True override, and a tunable failover_total_timeout to trade latency for more aggressive retrying. The SDK never escalates aggression on the caller's behalf.

6.6  Streaming: fail-before-first-byte (per-provider mechanics)

Failover for streaming is permitted only before the first chunk is yielded to the user. Once SyncStreamWrapper/AsyncStreamWrapper yields chunk 1, the served provider is committed; later errors go to on_error (breaker records a health failure) but never trigger failover.

Corrected per-provider mechanics (verified):

  • OpenAI / Anthropic: .create(stream=True) runs raise_for_status() eagerly inside dispatch, so connection/status errors raise at dispatch time (failover-eligible, no bytes yielded). The loop-around-dispatch rule works directly.
  • Google: generate_content_stream is a lazy generator — no network call until first iteration. The dispatch-time loop sees no exception, so Google streaming failover is unreachable unless we force first-chunk materialization inside the loop (pull next()/anext() on the raw stream before wrapping, catch the establishment error there, re-yield the buffered first chunk from the wrapper). Decision A — streaming ships in v1: implement Google first-chunk materialization so its lazy generator is failover-eligible exactly like OpenAI/Anthropic. Streaming failover is NOT deferred; non-streaming-first is explicitly rejected as it would gut the marketing promise for the highest-value calls.

6.7  The honest millisecond claim

Once a provider is known-unhealthy (its circuit is OPEN), rerouting is instant — sub-millisecond, from local state, no server in the loop. Detecting that a healthy provider just went down still costs real time: the first failure_threshold requests must fail (bounded by your configured per-hop timeout, not the 600s SDK default) before the breaker opens. After that, every subsequent request reroutes instantly until the provider recovers. Process-local breakers start CLOSED, so this never covers the first failing request of a fresh process.

Privacy Firewall Design

Where translation lives. A single new content-privileged module src/solwyn/providers/_translation.py. Do not widen _privacy.py — its CI-enforced "no logging import / returns int only" guarantee is the strongest trust anchor and translation (which returns transformed structures) cannot satisfy it. The content-touching allowlist becomes exactly two modules: _privacy.py (returns lengths) and providers/_translation.py (returns transformed kwargs destined only for a provider SDK).

The content-touching contract — verbatim in module banner + CLAUDE.md
  1. In-memory transform only; store content nowhere long-lived.
  2. Output goes only to the destination provider SDK via the dispatch seam — never to _reporter, _budget, or any httpx client pointed at config.api_url.
  3. No logging of content at any level; import neither logging nor httpx; hold no logger.
  4. Fail loudly: UntranslatableRequestError(source, target, feature) with structural labels only (never the offending value).
  5. Exception messages/__notes__/__cause__ carry no content: re-raise across the boundary with raise UntranslatableRequestError(...) from None (suppress __context__); attach only type(exc).__name__.
  6. Length/token estimation routes through _privacy.estimate_content_length on the translated kwargs (so budget reflects the provider actually called). _translation.py returns no lengths.
  7. Solwyn wire models stay content-free (extra="forbid"); only structural additions (provider identifiers) allowed.
  8. Pure, no I/O.

New leak vectors failover introduces, and closures

  • add_note on a shared exception (client.py:308/624 already interpolates type(exc).__name__ — safe). Provider SDK BadRequestError embeds request content in str(exc)/.body. Close: firewall assertion forbidding add_note(f"…") with any interpolation other than type(...).__name__; never stringify a provider exception into a Solwyn payload/logger.
  • Logging of kwargs dicts. The bareword regex (\bmessages\b, …) misses kwargs/fallback_kwargs/translated_kwargs/call_kwargs/payload/request_body. Close: extend the regex.
  • exc_info=True with a provider exception in scope. Close: _translation.py has no logger at all; assert no logger.*(..., exc_info=True) in the failover except-blocks where a provider exception is live.
  • _AttemptContext holds kwargs. Close: assert it is never .model_dump()'d into an event or passed to a logger.

Decision · Reserve against primary, confirm authoritatively

Keep one reservation per logical call, priced against the primary at check time (O(1), cheap). Make confirm authoritative by sending the actually served provider+model so the Cloud API re-prices real usage. This avoids the systematic over-reservation that full-chain pre-authorization causes on the common no-failover path. The SDK still never computes cost.

8.3  Cloud API behavior

  • /budgets/check: price estimate against PRIMARY (O(1)); persist reserved_provider/model, declared_chain, and a TTL on the reservation. In HARD_DENY may verify ≥1 chain tier has headroom and apply a precomputed chain margin (no per-tier pricing on the hot path).
  • /budgets/confirm: look up reservation; if served provider/model ≠ reserved, validate membership in declared_chain; price token_details against the served provider; atomically release the primary-priced hold and apply real cost; idempotent on reservation_id.
  • Reservation TTL is load-bearing for reliability: on a correctly-not-failed-over post-send-ambiguous abort, no token_details arrive and confirm never fires — the hold must expire server-side, else HARD_DENY headroom leaks. The SDK emits an ERROR MetadataEvent with possibly_succeeded=True for reconciliation.
  • /metadata/ingest: accept the new optional fields (additive; deploy before the SDK sends them or ingest 422s). Old no-failover events are byte-identical (None-skipped).
  • Spend reconciliation (resolves OQ5, the cache-hit hole — §8.4): the ingest pipeline becomes authoritative for actual spend, not just observability. For any call whose served-provider MetadataEvent carries token_details but has no matching /budgets/confirm (joined by call_id) — i.e. budget-cache hits and abandoned-stream confirms — the Cloud API prices the tokens against the served provider and applies them to the budget ledger. Idempotent and deduplicated on call_id, so each call is counted exactly once whether it settled via confirm or via metadata.

8.4  Two accounting holes to handle explicitly

  • Cache-hit calls have reservation_id=None (budget.py deliberately does not reuse reservations), so no confirm fires and a cached-allow call that fails over to a pricier provider would be invisible to budget. Resolved (Cloud-API fix, OQ5): keep the budget cache and make the Cloud API reconcile actual spend from the served-provider MetadataEvent — priced against the served provider, joined and deduped against any confirm by call_id (§8.3). Trade-off accepted: HARD_DENY enforcement on a cached call is eventually-consistent (the ledger is corrected when the metadata event is ingested) — which is already inherent to any budget cache.
  • Streaming confirm is fire-and-forget via reporter.report_confirm; a dropped/abandoned-stream confirm leaves the cheaper primary estimate. Reservation TTL + the served-provider metadata event are the backstop.

Failover rate = count(is_provider_fallback)/count(*); requested-vs-served confusion matrix; failover_reason × failover_error_class distribution (proactive breaker-open vs hard error); exact cost attribution (confirm prices the served provider); attempt_index funnel (how deep the chain is exercised); confirm-vs-metadata served-provider cross-check as an SDK-bug tripwire. Per-provider default_params plus a global default_params, applied fill-absent-only (per-call > per-entry > global). A request that omits max_tokens and fails into Anthropic is filled from the Anthropic entry's default. RAISE only if still absent after defaults and the target requires it.

Resolved · 4 — Tools in the v1 subset (Decision B)

Yes for the converged custom-function contract (declaration + tool_choice + fully-resolved histories). Fail loud on dangling/unresolved tool calls, parallel same-name calls, and proprietary tools. Round-trip tests are the drift alarm; a tool_call_not_failoverable metric drives data-driven expansion. Not a perpetual-patch surface, because proprietary tools are never chased.

Resolved · 7 — failover_idempotency default (Decision C)

safe (no double-charge) is the default and floor; aggression is explicit opt-in (always / per-call solwyn_idempotent / tunable failover_total_timeout). The "first request to a hard-down provider still errors until the breaker opens" cost is accepted.

Constraint · Provider credentials out of scope (Decision D)

Solwyn never accepts, stores, or logs provider API keys (or prompts). Creds come only from the caller's client objects; the SDK documents that each chain provider must be configured. ProviderEntry has no api_key/base_url.

Resolved · 6 — Provider-SDK version floors (Decision F)

Declare minimum-version floors for the provider libraries in the install extras (solwyn[openai]/[anthropic]/[google]) so exception classes, max_completion_tokens, and the google-genai surface are predictable. Core still depends only on httpx+pydantic; status-first classification (§6.1) stays the runtime net for BYO installs below the floor. Concrete floor versions: TBD (pick current stable minimums).

Resolved · 5 — Cache-hit budget hole (Cloud-API fix)

Fix it in the Cloud API: keep the budget-check cache and make the metadata ingest pipeline authoritative for spend — price the served-provider MetadataEvent into the ledger, joined and deduped against any /budgets/confirm by a new per-call call_id (§8.3–§8.4). One mechanism closes both the cache-hit hole and the abandoned-stream confirm gap.
