Grounding Context

Codebase context. Solwyn Python SDK v0.4.x is a privacy-first drop-in wrapper (Solwyn/AsyncSolwyn) around openai, anthropic, google-genai, and boto3 bedrock-runtime clients plus ~14 OpenAI-compatible providers via base_url detection. It extracts token usage, runs pre-flight budget checks against the Solwyn Cloud API (which owns all pricing), settles usage off-thread with at-least-once delivery, and does health-based cross-provider failover. It never captures prompt or response content. Recent delivery: run-scoped token leases, settlement reliability, failover ergonomics, run hierarchy/inherited tags (PR #50). Pre-launch, zero customers — breaking changes are cheap right now. Test posture is strong (87 test files, privacy firewall + live wire-contract tests).

Known gaps found in the scan. CostPolicy is selectable but inert (no server price hints yet; falls back to health ordering with a one-time warning). Unrecognized client surfaces pass through with at most a warn-once (vs Bedrock invoke_model, which fails loud). No CI dry-run mode — budget checks always hit a live API. No framework integrations exist; the wrapper fails frameworks' isinstance checks. No loop/retry-storm detection, no mid-run kill switch. Same-name compat providers share one health domain (known limitation).

External context. Market research (reused from a parallel session plus a fresh SDK-layer pass): provider and gateway hard caps are commoditizing; the unclaimed gaps are mid-run termination, loop/retry-storm detection, identity-aggregated budgets, and denied-spend reporting. Runaway-agent postmortems are a genre ($47K/11-day ping-pong loop; $4.2K/63h retry loop). At the SDK layer: AgentBudget (closest competitor) ships LangChain/CrewAI budget glue with no cloud account; the OpenAI Agents SDK deliberately ships no budget primitive; OTel GenAI semconv is still in Development status with no cost attribute (validating server-side pricing); streaming-usage extraction bugs and upstream SDK version churn are recurring cross-vendor pain.

1 runaway-protection Confidence 85% Complexity High

Runaway Protection Flagship: detect → terminate → prove

Description
One program, three deliverables riding shared machinery. Detect: a content-free velocity engine (card-network-style rules over call sizes, cadence, and run identity — N near-identical-size calls in M seconds, monotonically growing context, call-rate acceleration) that flags retry storms and agent ping-pong without ever seeing prompt content. Terminate: a server-pushed terminate_run directive riding the existing budget-check and lease-renewal channel, enforced through the existing sticky per-run denial cache, plus a dashboard "kill this run" button — the run stops within one call or one renewal. Prove: denial receipts — every deny (server, sticky replay, or local breaker-open) becomes a durable event through the reporter, powering a "what the cap saved you" number.
Basis
direct: the runaway dossier lists exactly these as missing ("client-side runaway_run enforcement, mid-run kill-switch API, retry-storm detection"); verified seams: check requests already carry model/provider/estimated-tokens/run-id (budget.py:263-272), the server-directive pattern already works (_apply_failover_tuning_directive, _base.py:620-677), sticky per-run denial replay exists (budget.py:328-336), and the hard-deny path currently emits nothing durable (budget.py:407-477). external: market research names mid-run termination, loop detection, and denied-spend reporting as the three biggest unclaimed gaps; $47K and $4.2K loop postmortems are the category's defining horror stories; AWS Budgets Actions is prior art for typed, auditable breach actions.
Rationale
This claims the flagship differentiator while the whole market looks the other way — caps are commoditizing, but nobody stops a loop mid-run. Privacy becomes the moat instead of a limitation: competitors that detect loops server-side must ingest prompts; Solwyn detects client-side and transmits only the verdict. Roughly 80% of the machinery already exists, so this is assembly plus one wire field plus a detection module, not new infrastructure. The demo writes itself: "we detected the $47K loop, you killed it from the dashboard, here's the receipt."
Downsides
Cross-repo: needs API-contract and dashboard work in lockstep. False-positive posture for the velocity rules needs careful design (warn-first, then deny). Streaming abort semantics (stopping iteration between chunks) need a crisp contract. Nuance from verification: the first live hard-deny is already server-visible; it is the sticky/local replays that are invisible today.
2 ecosystem-integrations Confidence 80% Complexity Medium

Ecosystem Admission Pack: type-transparent wrapper + framework glue

Description
Two coupled moves. Enabler: make the wrapper pass frameworks' client validation — a wrapt-ObjectProxy-style transparent proxy (or runtime subclass of the caller's own client class) so isinstance(Solwyn(OpenAI()), openai.OpenAI) is true, with no provider imports in core (stays duck-typed). Distribution: a thin integration pack where the buyers are — a documented OpenAI Agents SDK recipe (set_default_openai_client(Solwyn(...)) with per-agent/handoff run scoping), a LangChain/LangGraph callback, and CrewAI middleware — all built on the run-hierarchy and tags event contract that just landed (PR #50).
Basis
direct: the ecosystem dossier's headline pain: the wrapper does not override __instancecheck__, so frameworks that validate provider client types reject it; grep confirms zero framework integrations exist while seven integration seams (run scoping, hierarchy fields, fire-and-forget reporter) sit ready. external: strands-agents#1103 shows users demanding injectable pre-configured clients; AgentBudget already ships LangChain callback + CrewAI middleware; the OpenAI Agents SDK deliberately ships no budget primitive — a vacuum.
Rationale
Agent frameworks are where runaway-spend buyers already are, and the closest competitor wins evaluations today purely on "works inside my framework." The type-identity fix is one mechanism that unblocks every injectable-client path at once — cheaper and more durable than N bespoke adapters — and the glue on top is mostly docs and thin callbacks over finished seams. The same proxy concept ports to the TS SDK (JS Proxy), so the design pays twice.
Downsides
Transparent proxying trades away implementation simplicity (pickling, attribute shadowing, __init__ bypass edge cases need tests). Framework APIs churn, so glue carries a maintenance tail — keep adapters thin and contract-driven. Choosing which frameworks get first-party support is a roadmap call.
3 attach-ergonomics Confidence 90% Complexity Medium

Deterministic control-plane test double (solwyn.testing)

Description
An in-process control-plane double plus deterministic scenario triggers, modeled on Stripe's magic test cards. A magic tag or model name deterministically produces a hard deny, a lease 503, a control-plane outage, slow settlement, or a runaway-run denial — so teams can exercise BudgetExceededError handling, fail-open posture, and exit-flush behavior in CI with zero network and zero credentials. The same scenarios double as chaos game days for spend infrastructure, and as Solwyn's own integration-test harness.
Basis
direct: BudgetMode has exactly two values, ALERT_ONLY and HARD_DENY (_types.py:46-51, verified) — no dry-run or offline mode exists, and the attach dossier confirms budget checks always hit a real API (the repo's own integration tests need a live server at localhost:8080). external: Stripe's deterministic test cards are the industry-standard pattern for making an external authorization plane testable; chaos-engineering game days are the same premise for failure paths.
Rationale
An enforcement SDK's deny path is the product, and today the first time a customer's deny handler runs is in production. This removes the biggest adoption objection ("how do I test this without your prod API?") once, in the SDK, instead of every adopting team building a fake server. It is the highest-confidence, most self-contained project on this list — no cross-repo dependency.
Downsides
Scoping how much of the control-plane contract the double must faithfully simulate (leases, directives, settlement acks) is the real design work — too little fidelity and tests lie, too much and it becomes a second server. A deliberately-cut LocalBudget/freemium variant was rejected (see Rejection Summary) — this project must not drift into local pricing.
4 provider-surface-coverage Confidence 85% Complexity Low

Coverage strict mode + coverage manifest

Description
Aviation's Minimum Equipment List applied to spend surfaces: nothing flies unlisted. (a) A solwyn.coverage() manifest reporting every surface of the attached client as metered / estimated / warn-once / pass-through, assertable in CI; (b) an opt-in on_unmetered="warn" | "raise" | "allow" posture where a spend-shaped surface outside the tracked set raises unless explicitly acknowledged (acknowledge_untracked=["translations"]).
Basis
direct: verified internal inconsistency — Bedrock invoke_model fails loud because "silent pass-through would be a budget bypass," while every other unrecognized surface warn-onces and passes through forever (client.py:1810-1816); the known-unmetered registry has exactly one entry (_base.py:143-145). external: LangSmith's wrap_openai missing the Responses API (langsmith-sdk#1588) is the canonical case of wrapper coverage silently rotting as providers add surfaces.
Rationale
For an enforcement-first product, a silently untracked surface is a hole in the fence exactly where customers assume there isn't one — and the current posture guarantees each new provider surface starts as a silent hole. Strict mode turns coverage drift from silent decay into a loud, auditable contract, is the client-side answer to gateways' "impossible to bypass" pitch, and is the cheapest project on this list relative to how directly it protects the core promise.
Downsides
Choosing the default posture (warn vs raise) is a real product-risk tradeoff — raise-by-default breaks innocent client.files.list() calls. Needs a maintained classification of which surfaces are spend-shaped vs metadata-shaped per provider.
5 cost-aware-routing Confidence 70% Complexity Medium-High

Graduated budget pressure + cost-aware degrade ladder

Description
Break "budget answers are binary." The server sends a pressure tier on check responses and lease renewals (zero extra round-trips, riding the proven directive pattern): at ~80% of budget the SDK flips chain ordering to cost-first; at ~95% it prefers the customer's declared cheaper model entries; at 100% the existing hard deny applies. Every degradation is loudly tagged on events, never silent. Prerequisite folded in: the name-keyed health-domain identity fix (same-name compat entries currently share one health domain and skip sanitization), so routing decisions rest on correct per-endpoint state.
Basis
direct: CostPolicy is shipped but inert — README:424 says the API sends no price hints yet, and _routing.py:186 confirms the silent fall-back to health ordering; price_hints and failover_directive slots already exist on BudgetCheckResponse (_types.py:473-507, verified); check requests already send the element-aligned fallback chain the server would hint against (budget.py:263-272). README:225 documents the health-domain collision. external: utility demand response is the proven governance split — the server owns the price signal, the edge sheds load within owner-declared comfort bounds; Cloudflare's block-or-fallback shows degrade-on-exhaustion is becoming table stakes.
Rationale
Between "spend freely" and "hard stop" is where real teams live; with agentic workloads at 5–30x chat tokens, "finish the run cheaper" beats "die at the cap." The wire fields, the pure policy class, and the directive channel are all built and idle — this is the highest-leverage way to make dead code load-bearing, and it makes CostPolicy honest (today a user who selects it silently gets the default behavior).
Downsides
Hard dependency on the Core API shipping price hints and a pressure signal — a cross-repo commitment that must be sequenced (hence the lower confidence). Degrade semantics (which calls may be downgraded, how loudly) are a genuine product-design question. The health-domain prerequisite adds scope, but skipping it builds routing on a known landmine.
